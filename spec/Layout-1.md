# UICL Layout-1 布局与词法规范

# Layout-1：文法之前的布局契约

本文与 `meta/grammar.uicl` 共同规定结构化入口。文法使用 ITEM_BEGIN/ITEM_END 作为列表项边界；这些是词法器的逻辑 token，作者仍然写 `-`。

## 常规布局

UTF-8 结构化文件以 uicl 字符串版本头开始。词间需要空格，缩进以两空格递增；Tab 不允许作为结构化缩进。空行和独立 `//` 注释不改变块结构。顶层必须至少一个节点。行末或 EOF 产生 NL，空白/注释本身不产生语义条目。

在 NodeEntry 上下文，读取 Key/QName 后如果紧跟冒号则是属性，否则是节点。字符串键不允许作为节点种类。属性冒号后同一行可以有 InlineValue 或原文块开始；若只有换行，则必须有一个更深的非空 BlockValue。

BlockValue 首个有效条目为 `- ` 或单独 `-` 时选择数组，否则必须为 Key 冒号形式的记录。所选类别在该块内保持，混合节点和数据报错。单独标量不能占据 `key:` 下一层作为一个无标记值；应放回冒号同一行。

## 列表项逻辑边界

列表块中行首、正确缩进处的 `-` 后必须跟空格或换行，才是元素起始。`-10` 是负数字面量，不是元素标记。

词法器为每个列表元素生成 ITEM_BEGIN 和 ITEM_END，并按下列情况处理元素内容：

1. `- scalar` 或 `- [..]`：生成 InlineValue、NL，元素结束。下一层额外字段非法。
2. `- |` 或 `- ```lang`：按原文规则产生 RAW、NL，随后结束元素。
3. `-` 后立即换行：保持元素虚拟基线在连字符列，后续内容必须再缩进两空格，生成 NL INDENT BlockValue DEDENT。
4. `- key: value`：按虚拟记录处理。该 key 的逻辑列是连字符列加二。下一行同一元素其他 key 必须与之对齐；为整段生成 BlockRecord，不在每个续行前插入额外 INDENT。嵌套属性的子值则比 key 再深一级。
5. `- key:`：同上，key 的值必须在逻辑列再深一级；返回同级 key 表示继续同一条记录，返回连字符列并出现新 `-` 表示新元素。

先检查紧凑记录的 Key 冒号前缀，再选择 InlineValue；引号字符串、URI、函数参数和嵌套括号内的冒号不影响此选择。词法器必须了解字符串和括号边界，不能简单 split(':')。

例如：

```uicl
items:
  - name: "甲"
    tags:
      - read
      - write
  - name: "乙"
    tags: []
```

name 与 tags 为同一元素记录的字段；它们的逻辑列为 4，tags 的数组元素列为 6。第二个 name 属于新的列表项。ITEM_END 在返回新元素边界前发出。

## 原文块

`|` 和反引号围栏仅出现在一个属性值或列表值的开始位置。块内不识别节点、值标记或注释。RAW 的内部同时携带解码文字值、源字节范围、原文种类及围栏语言标签，不执行载荷。源换行保留，语义文字换行依主规范规范化。

列表 `- |` 的文字内容以连字符列加二为最小内容列。记录属性的文字内容以该属性列加二为内容列。围栏关闭必须匹配围栏长度和该载体的规定关闭列；未关闭时报错，不吞掉后续文档。

## 内联集合

为保持一行一项边界，1.0 候选的 `[]`、`{}`、节点 `()` 属性及表达式不能跨物理行续写。长集合使用块式写法；长文字用原文块。行内不允许尾随逗号。将来放开这些限制要以单独兼容扩展验证，而不是在本版本不同实现里自行选择。

## 词法 token

IDENT 为 ASCII 标识符；NUMBER 为无前导正负号的十进制整数或小数/指数，正负由语法处理。拒绝前导零、十六进制数值、NaN 和 Infinity。明确的 `true/false/null` 在值语境是字面量；在主文本位置仅作为字面文字。保留最长匹配的 ::、?.、??、比较运算符。非法或重复属性不是只靠 token 文法即可判定，应在结构/语义阶段检查。

文法树是格式定义数据。本包 tools/syntax.py 实现独立的逐行布局与表达式语法原型，但尚未从该文法树自动生成完整解析器；一致性范围见 reports。
