# Semaquil 1.0 语言设计基线

状态：**design-candidate.1（设计候选，不是生产标准或已完成实现）**。日期：2026-09-20。

推荐品牌：**Semaquil**；中文工作名：**意契**。描述性名称：Universal Intent & Contract Language，统一意图与契约语言。扩展名暂定 `.semaquil`；不另造三字母缩写。本次名称只是建议，尚未完成商标、域名和各软件包注册表核验。

本设计整合此前 AML 0.1、0.2、0.3、1.0、自描述规范、Markdown/HTML 原生承载、块式数组与对象，以及语法与契约分层讨论。它保留先前的安全与执行边界，显式记录本次收敛决定，不把自然语言说明当成已经可执行的检查器。

以下 MUST、MUST_NOT、SHOULD 表示本候选规范的要求。此文件是可直接作为 Markdown 阅读的完整设计说明；`meta/` 使用结构化 Semaquil 描述文法、形状、规范要求及用例清单。两种文件共享同一份语义设计，但本包没有新编译器或运行时。

## 1. 唯一定位

Semaquil 描述：**已有内容是什么、希望得到什么、允许怎样处理、怎样验证完成**。

它不是 YAML 的替换口号，不是新的通用算法语言，也不是一个更长的 prompt 模板。它是一套可由人和 Agent 共同编辑的契约体系，并提供多种有明确边界的承载形式。

同一段结构化内容不因换用模型、编辑器或代码生成目标而改变权限、类型和业务规则。模型可以提出契约变更；确定性编译器负责解释契约；经外部授权的运行时负责执行。

“逻辑完备”是对已声明领域的输入、输出、状态、错误、权限与副作用进行明确约定，不是声称 Core 可以计算所有算法。复杂算法通过有类型的源码模块、工具或沙箱组件接入。

## 2. 采用与不采用

| 采用 | 不采用 |
|---|---|
| 一套语义核心、结构化/Markdown/HTML 三种作者入口 | 所有文档强制改写成节点树 |
| YAML 风格块式数组与对象，保留紧凑形式 | 引入完整 YAML 标签、锚点、别名及隐式标量规则 |
| 一个可选的主文本槽位 | 多个位置参数和运行时猜测含义 |
| `#` 身份、`@` 引用、`$` 取值、`=` 计算 | 同时引入 `${}`、模板反引号、隐式变量插值 |
| 稳定版本的领域词汇和组合构件 | 由模型猜测未知关键字或任意同义词 |
| 显式生成/调用/发布计划 | 打开文件、预览、引用输出即自动执行 |
| 字节、原文和语义投影并存 | Base64 化后就声称理解了所有格式 |
| 可验证的约束与独立评审 | 字段写了 require 就声称生成结果一定正确 |
| JSON/YAML 作为严格的契约数据映射 | 把任意 JSON/YAML 字符串自动提升成执行代码 |

## 3. 四层架构

```
表达层
  结构化 Semaquil / Markdown 宿主 / HTML 宿主 / 类型化数据交换
      ↓
契约层
  身份、类型、引用、表达式、依赖、权限、效果、证据
      ↓
领域层（Profiles）
  资源 / 内容生成 / 应用 / Agent / 生命周期 / 数据集 / 元规范
      ↓
适配层
  格式导入导出、渲染器、模型提供方、数据库、沙箱、部署环境
```

Profile 定义词汇及可执行含义，不得修改 Core 标点或类型规则。适配器声明实现了哪些能力，不得悄悄将硬要求降级成提示词。

一份文件可以同时描述多个领域，但用户只学习实际使用的部分。无界面服务、纯文档、纯设计稿都不必包进 `app`。

## 4. 新手只需三条结构规则

```
种类 "文字"
  属性: 值
  子节点
```

实际最小应用：

```semaquil
semaquil "1.0"
app "你好"
  ui.text "我的第一个应用"
```

完整节点形式仍为：

```
种类 [#身份] [主文本] [(属性: 值, ...)]
  属性: 值
  子节点
```

括号中的行内属性只是紧凑写法；默认教程与格式化风格优先使用展开属性。节点身份不被引用时可以省略。

## 5. 节点、对象、数组的边界

```
theme
  mode: system
```

这是节点；而：

```
theme:
  mode: system
```

这是对象属性。冒号决定进入值上下文，不依赖 Profile 猜测。

节点用于具有领域身份、组成、输入输出、约束或可复用意义的对象。对象值通常用于参数记录；数组用于有序数据。属性对象中的 `kind: button` 不会自动创建按钮，也不能携带执行权限。

在节点体中允许属性与子节点；在对象值体中只允许键值对；在数组体中只允许列表项。已知节点的未知属性报错。保存未知扩展源文档与执行未知扩展是两件不同的事。

## 6. 主文本槽位：一个位置，一个固定含义

每种节点由其锁定 Profile 声明零个或一个 `primary` 属性。主文本是该属性的语法糖。不得通过文案内容或模型猜测映射。

| 节点 | 主文本映射 |
|---|---|
| `app`、`page` | `title` |
| `ui.text` | `value` |
| `ui.button` | `label` |
| `image`、`video`、`deck` | `label`，不是生成提示词 |
| `field`、动作中的 `input` | `name` |
| `on` | `event` |
| `check` | `rule` |
| `criterion` | `text` |
| 未声明 primary 的节点 | 不接受位置主文本 |

例：`ui.text "欢迎"` 等价于 `ui.text` 加 `value: "欢迎"`。如果既使用主文本又显式指定同一个属性，即使值相同也报重复声明错误。

主文本可以是双引号字符串或单一简单裸词，例如 `on click`；不允许多个位置参数。`image "封面"` 不等于 `prompt: "封面"`。Profile 升级改变主文本映射属于破坏性变更，必须显式迁移。

## 7. 身份、引用和取值

| 语法 | 意义 |
|---|---|
| `#cover` | 为声明定义稳定身份 |
| `@cover` | 引用声明或已声明的资源句柄 |
| `@render.output` | 引用类型化输出端口 |
| `@brand::logo` | 引用导入模块的导出身份 |
| `@"./logo.png"` | URI 资源引用 |
| `$count` | 读取当前运行时值 |
| `= $count + 1` | 纯表达式 |

每个源码模块的显式 `#id` 必须唯一，嵌套节点不会意外形成同名的隐式模块。Profile 定义运行时数据绑定的作用域，如 `$input`、`$actor`、`$event`、`$props`、查询行及循环项。声明身份不意味着它一定导出 `$` 数据绑定。

被测试、外部引用或独立修改的节点必须有持久身份。匿名节点在当前构建内可以有临时标识，但不能声称它基于行号、内容哈希或兄弟序号跨编辑稳定。移动和重命名要维护引用；标题变化不应改变身份。

`@count` 是状态句柄，`$count` 是值。`set` 和可写输入绑定只允许经类型检查的 state；查询快照、props、actor 不可写。

## 8. 值与类型

基础值：`text`、有符号 64 位 `int`、精确 `decimal`、`bool`、`null`。领域类型包括 `id`、`date`、`instant`、`duration`、`bytes`。组合类型包括可空、列表、记录、枚举、类型引用及可验证的域类型。

- 整数字面量为 int；含小数点或指数的数字为 decimal。
- int 溢出报错；不自动转换成近似浮点。
- decimal 基线为至多 34 位有效数字，采用 decimal128 的指数范围；超界或隐式精度丢失报错。实现必须在契约中固定具体表示规则。
- int 与 decimal 不隐式混算；可使用显式转换。
- 日期、时间、URI、金额币种均不从普通字符串猜测。
- 仅 `true`、`false` 为布尔，`null` 为显式空值；`yes`、`no`、`on` 都是文字。
- 字符串不进行模板插值。中文短语、带空格或特殊符号的值使用双引号。
- 简单裸词和限定名可以作为字符串值。JSON/YAML 交换时不能依靠字符串外形决定类型。
- 空数组或 null 无法唯一推断类型时，需要 `type` 或外部输入契约。

`decimal128` 的实现细节与完整类型操作表属于编译器实现冻结前的必须完成项；本候选文件不宣称已经提供数值运行时。

## 9. 块式数组与对象

```semaquil
operations:
  - read
  - create
  - update

options:
  - label: "简体中文"
    value: "zh-CN"
  - label: "English"
    value: "en"

settings:
  appearance:
    mode: system
  retries: 3
```

数组元素有序且允许重复；对象键唯一，不定义业务顺序。键名中的点是键名的一部分，不自动展开嵌套表。语义规范化不能改变数组及子节点顺序。

紧凑写法继续合法：

```semaquil
size: [1200, 630]
settings: {mode: system, retries: 3}
items: []
metadata: {}
selected: null
```

未提供值的 `items:` 不是空数组、空对象或 null，必须报错。单独的 `-` 后面必须有一个缩进的非空值块。`- -10` 是包含负整数的一个元素。

`items: $tasks` 与 `items: [$tasks]` 不等价；后者在 `$tasks` 为列表时形成嵌套列表，不自动扁平化。

列表对象首字段可以放在 `-` 后面，后续字段与它对齐。嵌套数组推荐使用 `- [1, 2]`，也允许单独 `-` 后再写块式数组。整个块的类别由首个非空非注释项确定，不允许混入另一类别。

## 10. 文本、代码与词法

文件为 UTF-8，允许文件头 BOM。结构化缩进固定两空格，Tab 不自动变成空格；正文原文块中的 Tab 保留。CRLF/LF 均可读取，源码字节原样保留；词法解析可使用规范化的逻辑换行。

标识符采用 `[A-Za-z_][A-Za-z0-9_]*`；QName 是由点连接的标识符。资源标题与显示文字支持 Unicode。中文化编辑器可以提供固定词汇映射，不能将任意中文同义词解释成字段。

普通注释为独立 `//` 行，不采用 `#` 注释。核心不允许随意混入块注释、分号、多个节点同一行或正文插值。

`|` 是文字值块：按固定内容缩进去缩进，值的逻辑换行规范化为 LF；非空内容的末尾换行采用 clip 规则，去除多余空尾行并保留一个末尾 LF。需要字节级保留时使用 bytes，而不是依赖此文本值。

反引号围栏嵌入代码和原文；围栏内不解析 `#`、`@`、`$`、节点或注释，语言名不授权执行。围栏长度至少三，关闭围栏长度与开启一致且位于规定缩进；内容包含同长围栏时选更长的外层围栏。

字符串采用双引号及 JSON 风格转义；不允许未配对代理项、无效 UTF-8 或原始换行穿越字符串边界。单引号不作为第二套字符串语法。

## 11. 表达式与效果

直接 `$binding` 是表达式简写；复合表达式需要 `=`。表达式支持受控访问、可空访问、索引、列表/记录构造、算术、比较、布尔及空值合并。

优先级从低到高：`??`、`or`、`and`、`not`、比较/`in`、`+ -`、`* %`、一元 `-`、访问与调用。比较禁止隐式链式语义，例如 `a < b < c` 需要写成两个比较。`and/or/??` 短路求值。

Core 不提供隐式舍入的 `/`，除法使用显式精度与舍入模式的 `round_div`；余数操作只作用于整数，并采用向零截断商的余数规则。

表达式里的名字必须为已定义纯函数或显式 `$` 绑定。`= $status == "approved"` 合法；不把未解析的 `approved` 当变量或自动枚举。

表达式不执行网络、文件、数据库写入、密钥读取或任意 eval。函数来自锁定的纯函数注册表；实现必须限制输入大小、执行步数和递归深度。复杂算法通过能力接口或代码模块，不扩张为第二套通用编程语言。

## 12. 单一语义图与多种承载

结构化文件以 `semaquil "1.0"` 开始。Markdown 和 HTML 采用专用宿主标记。扩展名只用于提示，不授予执行权，也不代替版本声明。

JSON 为规范机器交换形式，YAML 可以作为等价映射的作者输入。它们承载有类型的契约对象，而不是任意 YAML 自动具有 Semaquil 语义。TOML、XML、原生源码通过资源或适配器接入；1.0 不强求为每种格式维护一套完整作者前端。

所有已支持前端进入同一类型、引用、效果与权限检查器。前端 A 禁止的操作，不能通过前端 B 绕过。

## 13. 原生 Markdown

```markdown
<!-- semaquil:markdown 1.0 -->

# 产品说明

这是一份 **正常的 Markdown 文档**。
```

保留原生正文，只增加一个不可见声明。后缀可以在 `.semaquil` 和 `.md` 间修改而不改字节。

基线固定 CommonMark 0.31.2；GFM 等扩展需要锁定版本。兼容承诺是指定宿主方言下的正文格式与静态可见内容，不是所有阅读器像素一致。禁止在 AML/Semaquil 解析失败后悄悄回退到 Markdown。

无标记旧 Markdown 可以在上层显式指定 host=markdown 后作为被动文档导入；不自动激活正文中的契约。解析代码围栏和普通文字不等于执行。

## 14. 注解岛及绑定

```markdown
<!-- semaquil:markdown 1.0 -->

# 产品说明

<!-- semaquil
doc.block #summary
  target: next
  intent: "简短说明产品解决的问题。"
-->

这款工具帮助读者整理资料，并保留原有排版。
```

宿主解析器先识别真实注释，Core 解析器随后读取其载荷。不能用正则扫描所有 `<!-- semaquil`，否则围栏中的教程也会被激活。

第一阶段只允许 Markdown 文档级、列 0、独立块边界处的活动注解。`next` 指向其后的第一个同级内容块，忽略空白及已识别的注解；无目标报错，不进行语义相似匹配。

注解岛共享文档模块作用域，并保留源码位置。正文移动导致绑定变化时必须可见；机器补丁要检查预期源摘要。正文中的 `#`、`@`、`$` 保持宿主含义。

正文是当前发布内容的唯一事实来源。注解存规格、约束、血缘和可审阅的变更计划，不保存另一份独立可编辑的正文。

## 15. 原生 HTML

```html
<!doctype html>
<html lang="zh-CN">
<head>
  <meta charset="utf-8">
  <!-- semaquil:html 1.0 -->
  <title>产品说明</title>
</head>
<body>
  <p id="summary">保留 <strong>HTML</strong> 排版。</p>
  <!-- semaquil
  doc.block #summary_contract
    target: {html_id: "summary"}
  -->
</body>
</html>
```

HTML 注解载体对载荷去除统一边距后解析，保存源位置映射。绑定精确匹配现有 HTML ID；缺失或重复目标报错。原始源码不因为解析发生变化。

可选的 HTML 数据载体为 `<script type="text/plain" data-semaquil>`，载荷是完整结构化文档。它不用于通用 Markdown 承载，因为渲染器过滤策略存在差异。

注释与 script 结束边界必须由宿主安全序列化器校验。不能靠 AML/Semaquil 引号屏蔽 `-->` 或 `</script>`；适合字符串的内容可使用 Unicode 转义，不适合的载荷通过下节编码载体。

HTML 的原有脚本和 CSS 可能观察 DOM 变化。这里不承诺任意脚本在加入注释后行为绝对不变，更不承诺 `.html` 改后缀后所有服务器路由、MIME 或自身 URL 行为不变。原生预览与隔离安全预览必须区分。

## 16. 复杂注解载荷的确定性编码

新增两个可选载体，避免注释终止符使契约截断：

```
<!-- semaquil:base64url
<无填充 Base64url 编码的 UTF-8 节点片段；规范输出每行 64 字符>
-->
```

```
<script type="text/plain" data-semaquil-encoding="base64url">
<无填充 Base64url 编码的完整结构化文档>
</script>
```

载体的编码是对整个 UTF-8 载荷一次编码后折行；允许移除 ASCII 空白再严格解码。它与 HEXL 的“逐原始字节块独立编码”不同，不应混用解码算法。应检查 pad bits、编码字母表、UTF-8、大小上限以及版本一致性。

编码载体是兼容逃逸方式，不是默认作者写法。编辑器应展示解码后内容；注释不是秘密，编码也不是加密或授权。

## 17. 无损编辑与格式检测

保留原始字节、宿主 CST/AST、Core AST、源码映射和契约图。无操作保存字节不变；局部编辑不改变范围外字节。格式化必须是显式操作，不能从 AST 全量回写破坏 Markdown 行尾空格、HTML 实体、属性顺序或编码标记。

格式检测顺序：受信的外部模式参数，与文档显式头交叉检查；结构化版本头；Markdown 开头的真实标记；HTML head 中的真实标记。冲突、重复或不支持版本报错。代码、字符串、textarea、template、script/style 内容中的伪标记不改变模式。

单文件不意味着所有图片都内联。读取相对资源一般以源文件为基准；HTML DOM 原生资源继续遵循 HTML 自身的解析规则，包括 `<base>`，但契约资源的基地址不受任意宿主 `<base>` 授权性劫持。两者要在工具中明确区分。

## 18. 资源体系

资源由身份、URI、内容摘要、媒体类型、版本、血缘与访问要求组成。这些字段互不替代。

```
@cover
@render.output
@brand::logo
@"./assets/logo.png"
@"file:///C:/Reports/report.pdf"
@"https://example.org/report.pdf"
@"appres://design/project_123/layer_456"
```

相对 URI 按声明所在模块的基 URI 解析，不以进程工作目录解析。`appres` 是待实现的宿主资源代理协议，不声称已经注册。绑定由宿主提供；授权不能从 URI 字面量推导。

加载源码默认不联网、不读取任意路径、不加载动态库。外部资源只有在受控解析任务中才访问；必须限制路径、重定向、协议、大小、私网目标和递归依赖。发布构建需锁定可变输入的实际摘要。

导入模块的 export 列表、别名和版本必须明确；同名导入不自动覆盖。资源图可以有引用循环，但构建依赖、值依赖与任务依赖分别检查其循环规则，不因为存在图循环就允许无限执行。

## 19. 文件的三种表示

| 表示 | 承诺 | 边界 |
|---|---|---|
| 原生文本 | 保留语言源码并声明用途 | 不等于执行，不必翻译成 Semaquil |
| 原始字节 | 精确重建任何有限文件载荷 | 不包括文件系统权限等外部元数据 |
| 语义投影 | 通过适配器获得可编辑结构 | 必须声明覆盖范围、损失与保真等级 |

推荐原始字节和语义投影同时存在，但明确哪一个是编辑事实来源。投影必须绑定源摘要和适配器版本；修改投影后生成的是新产物，不能继续声称原文件字节一致。

JPEG/PNG、PDF/DOCX、EXE/DLL/SO、专有二进制都可以承载为字节。没有适配器时只报告“不透明资源”，不伪造其内部结构。

## 20. HEXL/1 保留为独立协议

```
!hexl 1 <encoding> <chunk_bytes>
<16位小写十六进制原始偏移>:<本块编码载荷>
!end <total_bytes> <line_count> sha256:<原始字节摘要>
```

支持 hex、base64、base64url 和 base32；固定字母表和规范填充规则以 RFC 4648 为基础。推荐每块 48 原始字节。先切原始字节，再逐块编码；解码也逐行独立进行。偏移、尾部总长、行数及摘要必须吻合。

`hex` 使用小写字符；base64 使用规范填充；base64url/base32 采用本协议明确的无填充形式。非末尾数据块必须满长；尾块不为空；空文件没有数据行。块长应限定为正整数并受实现硬上限约束；基线接受上限为 1 MiB。

拒绝重复、乱序、缺块、错误字符、错误 pad bits、终止之后的非空数据。先写临时文件，完整验证通过后原子发布。摘要证明完整性而非可信来源；签名和发布权限另行验证。

这是可流式文本封装，不是压缩。大型资源优先旁挂或内容寻址存储。随机块认证需要另外的分块摘要或 Merkle 扩展，基础协议不承诺。

## 21. 规格、生成器、任务、产物和槽位

| 类型 | 含义 |
|---|---|
| `Spec<T>` | 希望得到怎样的内容 |
| `Generator<I,O>` | 有输入输出、预算与效果的生成能力 |
| `Task<T>` | 一次经过规划和授权的执行实例 |
| `Artifact<T>` | 实际存在、有摘要与来源的产物 |
| `Slot<T>` | 可装入某类产物的动态区域 |

`image` 是图片规格；`ui.image` 是显示图片的控件。`generate` 引用 Spec，输出端口在成功执行后才提供 Artifact。引用端口建立依赖，不自动调用模型。

类型检查不能把 Spec 当 Artifact，也不能让任何字符串或任意 JSON 冒充已验证的 UI 树。产物验证与发布批准分别记录。

## 22. AIGC 的三种要求

硬检查、偏好与评审分离：

- `require/check`：已登记且适用的规则，可返回 PASS/FAIL/ERROR/NOT_EVALUATED。
- `prefer`：优化目标，不伪装成保证。
- `review/criterion`：自然语言评价维度，绑定人工或评估器证据。

只有明确通过的必需项才能通过发布门禁。评估器不可用不是 PASS。产物、规格、验证器版本和检查输入摘要绑定在同一证据记录中。

尺寸、轨道边界、幻灯片数、文件媒体类型可机械验证；主体自然、结论可信等可能需要评审。模型评价与人工意见不能替代所有确定性检查。

图像精确文字宜使用独立排版层合成。视频用整数帧或整数 tick 加有理数时间基准。PPT 声明可编辑文字后，导出器不能只提供每页截图。CAD/3D/UI 设计通过各自的结构类型与保真要求接入。

## 23. 渐进式应用

L0：静态内容；L1：状态与事件；L2：collection/form/list；L3：model/query/action/policy/workflow/capability。它们是学习层级，不是四门语言，也不用写 level。

`app` 直接包含界面节点时，按固定 recipe 展开出默认页面和布局，不自动生成账户或服务器。多页面可以显式展开，保持原有语义。

`collection` 默认只启用 read/create，不隐式启用 update/delete。必须明确 storage=device/server；服务端需 access 或显式 policy，缺失不能上线。`owner` 展开为服务端所有权策略，身份不能由客户端任意指定。

form 负责输入、校验、提交状态、失败保留输入、请求去重；list 负责加载、错误、空态及有界分页。其行为由版本化 recipe 定义并可展开查看，不由模型补写。

设备存储改成服务端存储是有隐私和数据迁移影响的变更，不能自动上传旧数据。

## 24. 业务运行语义

- 身份和模型权限由服务端执行，未声明默认拒绝；前端隐藏不能代替授权。
- 查询策略在分页、计数和聚合之前应用，禁止全量返回后由前端过滤。
- 顺序动作等待前一步成功；失败停止，除非显式声明异常路径。
- 写入使用事务、约束和并发版本检查；事务不能撤销外部世界。
- 事务中外部效果通过 outbox 或受控编排，不直接跨网络假装原子。
- 幂等键绑定请求身份、范围和规范化输入摘要；同键不同输入报错。
- 外部任务超时可能为 INDETERMINATE；未知是否执行时不能无条件重试付款等操作。
- 工作流受保护字段只能由合法 transition 原子更新；transition 授权还需与模型策略共同成立。
- HTTP API 显式暴露，不因存在 model 自动开放 CRUD。
- 动态响应遵循最新请求获胜；取消不等于撤销已提交的服务端动作。

这些继承之前 AML 应用契约的设计方向，不是本包已实现的运行能力。

## 25. Agent

Agent 契约包含输入、输出、指令、工具、记忆范围、预算、停止条件和人工升级路径。

`instructions` 是行为意图；`agent_policy` 与宿主权限负责强制执行。工具、网页、附件、模型输出和嵌套契约都属于不可信输入，不能通过一句“授权已获得”提升权限。

工具列表与输入输出类型必须固定；MCP 等协议是工具适配入口，不替代完整 Agent 的权限、预算、记忆和状态规范。密钥由宿主按最小权限注入，不能写入源文件。

多 Agent 委托采用共享预算和权限交集，子 Agent 不可扩大父级授权、递归深度或网络范围。记忆的保存、检索、跨租户隔离和删除有明确契约。

## 26. 传统逻辑与模型推断混合

执行语义区分确定性计算、模型推断、外部效果，不按 CPU/GPU 硬件决定语言含义。

`infer` 的输出必须落在指定类型和枚举中，并经本地验证。超时、拒绝、非法输出、无法判断都有显式路径。对分类结果使用固定处理器分派，不接受模型返回任意函数名作为命令。

模型输出符合 Schema 并不证明结论正确。高影响操作还需业务校验和外部授权。重放应固定历史推断产物，不以相同 seed 代替可复现保证。

## 27. 动态 UI、图像与嵌套应用

Slot 声明 Generator、输入、触发条件、回退与版本。默认只显式触发；刷新页面或读取引用不自动生成。运行时必须实现去重、取消、预算、旧响应不覆盖新响应以及卸载清理。

动态 UI 优先输出受限 `ui.tree`。宿主限制组件集、节点数、深度、可绑定数据和可用动作；生成结果不直接注入任意 HTML/JS。

需要自定义算法的子应用可以输出 `wasm.component`。必须明确宿主接口、imports、内存、fuel/时间、网络、文件和嵌套上限。Wasm 是执行隔离工具，不自带正确性、UI、授权或无限资源保护；实际能力取决于宿主实现。

## 28. 设计、测试、构建、部署、观测

需求 → 设计 → 契约/源码 → 生成/处理 → 验证 → 构建 → 发布 → 观测 → 迭代。

设计包括 token、主题、布局、资源、多语言和可访问性目标；目标声明不等于已达标。

测试采用 given/when/then 节点，操作和断言都有类型。稳定身份用于定位，测试实例必须隔离。生成的基础测试与业务验收分开；测试关联需求不等于覆盖充分。

构建产物不可变并有摘要。部署先产生资源/费用/权限/数据迁移计划，再由外部审批及授权执行。源文件里的 approval 字段只请求门禁，不是已获得批准。

应用版本回退、数据库结构回退和业务数据恢复独立建模。破坏性迁移不在应用启动时自动执行。日志、指标、追踪默认不记录敏感正文；未授权接收端不自动上传。

## 29. 训练数据与血缘

训练样本包括规格、输入、原文/字节/投影、目标、实际产物、评估证据、来源、许可和敏感性。

存档层可以用 Semaquil + HEXL；训练加载层应把原生图像/音视频解码为对应模态，不能把 Base64 字符串直接当作视觉语义。

原文、截图、译文和语义投影若来自同一来源，需要同一分组避免跨训练/评估集泄漏。派生关系与内容摘要都应记录。未知许可和同意不自动允许训练或再分发。

统一格式是否提高模型能力是待检验假设，不因新语言更结构化而直接认定。需要与 Markdown、YAML/JSON 契约对照，控制任务、模型和预算。

## 30. Profile 与默认规则的版本

语言版本、标准词汇版本、外部 Profile 版本和具体适配器版本分别锁定。基础版本可附带一个固定标准词汇目录，用户不必手工写所有 import；新词汇不能悄悄改变旧版解析含义。

Profile 至少声明：标识、版本、节点 shape、primary、属性类型、子节点规则、端口、效果、验证器、默认 recipe 和兼容性。

未知 Profile 可被编辑器作为不透明源片段保存；主动目标依赖它时不得生成成功执行计划。未知属性不能被 AI 自动修正为近似名称后发布。

`.akml` 和 `.svml` 是特定平台的 Profile 组合与文件关联，不修改核心语法，不重新解释符号；本包不实现两种目标方言。

## 31. 类型化交换模型

规范化节点包含：kind、可选 identity、typed properties、有序 children。位置主文本展开到普通属性；不同时保留两个互相矛盾的可编辑值。

交换层所有值显式标注 tag，例如 text、bool、int、decimal、list、record、ref、expr。大整数和 decimal 使用规范十进制字符串；日期和字节也有各自 tag。

普通文字 `"@logo"` 编码为 text，不因外形变成引用。record 使用唯一字符串键；没有任意混用 `$ref` 魔术字段与用户对象的规则。

表达式输出结构化树，不以任意源代码字符串承载执行含义。没有通过类型和效果检查的表达式只能标记为未解析源码。

源文件、作者契约、展开构建计划与实际产物分别计算摘要，不能把它们混为一个 hash。域/版本和所有执行相关值纳入哈希输入；JCS 可用于最终 JSON 规范化，前提是先完成无损类型编码。

## 32. 编译器与运行时分工

```
Source bytes + mode
 → Host/Core CST
 → AST
 → Profile/模块链接
 → 名称与类型解析
 → 纯表达式和效果检查
 → 确定性默认展开
 → Contract Graph
 → Plan
 → 外部授权
 → Adapter 执行
 → 验证/评审
 → Artifact + Evidence
```

源映射覆盖隐式生成节点；每个节点可解释来自源码、默认规则还是上一次 Agent 修改。

执行计划不得绕过静态检查。解释执行和代码生成必须通过相同的行为一致性测试。离线检查不调用模型；模型不可用不应改变已发布确定性业务逻辑。

解析器、结构检查器、语义编译器、运行时、适配器和编辑 Agent 分别报告实现范围。语法合法不等于可构建，可构建不等于已授权，已授权不等于结果已通过验收。

## 33. 自描述与可信引导

`meta/grammar.semaquil` 使用 g.rule/g.seq/g.choice/g.repeat/g.ref/g.token/g.literal 描述结构文法；layout 规则也是显式规范对象。`meta/contracts.semaquil` 描述规则和节点 schema。

仍需受信的最小解析器读取元规范。自描述不等于编译器已经用该语言实现，更不是自动证明无漏洞。不能让任意文档携带的 schema 覆盖宿主的安全规则。

`rule.statement` 是规范正文；`verification` 指定测试或评审类型。未实现的检查必须报告 NOT_EVALUATED。被嵌入的 example 原文只用于学习或显式测试，不在解析阶段执行。

## 34. 错误与诊断

建议诊断包含 code、severity、phase、source span、related spans、path、说明与可选修复候选。

基线错误族：SYNTAX、LAYOUT、DUPLICATE_KEY、DUPLICATE_ID、PRIMARY_CONFLICT、UNKNOWN_PROFILE、UNKNOWN_PROPERTY、TYPE_MISMATCH、UNRESOLVED_REF、EFFECT_DENIED、BUDGET_EXCEEDED、CONFLICT、INDETERMINATE、VALIDATION_FAILED。

错误修复不能通过放宽权限、删除门禁、去掉测试或自动上传数据实现“检查通过”。对不可信文档显示的错误也应避免泄漏其他用户资源是否存在。

## 35. 1.0 收敛与迁移

此前 AML 文件保留其原版本与语义，不全局替换字符串后宣布迁移成功。

迁移顺序：按旧版解析 → 绑定旧版词汇与 primary → 构造旧契约 → 显式转换 → 生成新源码 → 比较类型、权限、效果、依赖与测试影响 → 审阅。

新增块式集合和 Host Documents 需要新前端；旧解析器不能直接识别。元规范新的 primary 映射、类型化数据交换和编码注解载体都是本次候选补充，不假装已包含在此前实现中。

名称决定与语法版本分离。Semaquil 是推荐工作名，正式采用前确认品牌资源；更名不应再次改变核心模型。

## 36. 建议的实现冻结顺序与验收

先完成 Core + 无损 CST + 块式集合 + 类型化 JSON + 自描述加载；再完成 Markdown/HTML 承载与身份补丁；随后打通一个设备端数据应用及一个生成内容任务；最后扩展服务端、Agent、沙箱和部署适配。

每个实现阶段必须通过对应测试：

1. 节点主文本与展开属性等价；重复字段拒绝。
2. 块式/紧凑列表和记录产生等价值。
3. @ 引用、$ 取值与字符串不混淆；表达式不执行副作用。
4. 文档改后缀字节不变；注释和代码边界识别正确；无操作保存一致。
5. 不透明资源与语义投影保真等级准确；HEXL 逐块重建并拒绝损坏。
6. 权限、事务、幂等、冲突、超时不确定和动态响应竞态一致。
7. 必需约束未评估时不发布；不可因换前端或适配器绕过限制。
8. Agent 修改展示来源与影响；旧摘要失效时拒绝补丁。

“最优”在这里表示对当前目标的推荐收敛：学习成本小、既有格式可用、语义明确、权限可控、实现可分阶段。不宣称已完成用户实验或优于所有其他语言。正式冻结前需进行与同语义 YAML/JSON 的对照试验。

## 37. 包内验证与未实现边界

本包提供设计文件、示例、结构化元规范与产物检查脚本。检查脚本只验证包结构、文档字节副本、样例载荷、JSON/YAML 值映射（环境支持时）和简单规则清单，不是语言编译器。

没有本次新语法的完整 parser、类型运行时、渲染器、数据库、AIGC 或 Agent 实现。此前 AML 的测试结果不计入本候选版本。例子中的 provider、模型、字体、adapter、外部 URI 和发布环境是接口契约，实际使用需要宿主绑定。
